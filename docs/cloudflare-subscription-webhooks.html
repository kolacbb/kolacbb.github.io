# Cloudflare Pages 订阅监听

这个仓库现在支持：

  • Google Play RTDN -> 拉取订阅详情 -> 推送到 webhook
  • App Store Server Notifications V2 -> 拉取/解析交易详情 -> 推送到 webhook

默认 webhook 可以直接配置成钉钉机器人。

# 接口

  • Google Play Pub/Sub push: /api/subscriptions/google
  • App Store Server Notifications V2: /api/subscriptions/apple
  • 健康检查: /api/subscriptions/health

# Cloudflare 环境变量

在 Cloudflare Pages 项目 wlang 里，先只看这 2 级。

# 第一层：必填

  • SUBSCRIPTION_WEBHOOK_URL 直接填你的钉钉机器人地址
  • DINGTALK_KEYWORD 填 App

# 第二层：建议填写

  • GOOGLE_ENDPOINT_SECRET
  • APPLE_ENDPOINT_SECRET

这两个 secret 用来保护回调入口，建议都配。

如果设置了 secret，请求可以通过以下任一方式带上：

  • Query: ?token=xxx
  • Header: x-endpoint-secret: xxx
  • Header: Authorization: Bearer xxx

# 第三层：只在“拉 Google 详情”时填写

  • GOOGLE_SERVICE_ACCOUNT_EMAIL
  • GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY

要求：

  • 这个 service account 需要有 Google Play Developer API 的读取权限
  • 私钥直接存 Cloudflare secret，保留 PEM 格式即可
  • 如果 Cloudflare UI 把换行压成了 \n，代码会自动处理

# 第四层：只在“拉 Apple 详情”时填写

  • APPLE_API_KEY_ID
  • APPLE_API_ISSUER_ID
  • APPLE_API_PRIVATE_KEY
  • APPLE_BUNDLE_ID

要求：

  • 使用 App Store Server API 的 .p8 私钥
  • APPLE_BUNDLE_ID 要和你的 app 对应

# Google Play 配置

Google Play 不会直接请求你的接口，而是：

Google Play -> Google Cloud Pub/Sub -> Pages /api/subscriptions/google

配置步骤：

  1. 在 Google Play Console 打开 Real-time developer notifications
  2. 绑定一个 Google Cloud Pub/Sub topic
  3. 给这个 topic 创建 push subscription
  4. push URL 配成：
https://你的域名/api/subscriptions/google?token=你的GOOGLE_ENDPOINT_SECRET

如果你不想配 GOOGLE_ENDPOINT_SECRET，也可以直接填：

https://你的域名/api/subscriptions/google

收到通知后，函数会继续调用 Google Play Developer API：

  • purchases.subscriptionsv2.get

当前会尽量补齐这些字段：

  • appId
  • userRegion
  • billingEventKind
  • subscriptionId
  • amount
  • expiryTime
  • subscriptionState

说明：

  • billingEventKind=purchase 对应 SUBSCRIPTION_PURCHASED
  • billingEventKind=renewal 对应 SUBSCRIPTION_RENEWED
  • Google 的金额优先取订阅详情里的价格字段，用来满足通知展示
  • 某些优惠价/试用价场景下，这个金额不一定等于用户那一笔真实扣款金额

# App Store 配置

在 App Store Connect 的 Server Notifications V2 里填写：

https://你的域名/api/subscriptions/apple?token=你的APPLE_ENDPOINT_SECRET

如果你不想配 APPLE_ENDPOINT_SECRET，也可以直接填：

https://你的域名/api/subscriptions/apple

收到通知后，函数会：

  1. 解析 signedPayload
  2. 读取 signedTransactionInfo / signedRenewalInfo
  3. 如果配置了 App Store Server API 凭证，再去拉一次交易详情

当前会尽量补齐这些字段：

  • appId
  • userRegion
  • billingEventKind
  • productId
  • amount
  • purchaseDate
  • expiresDate
  • autoRenewStatus

说明：

  • billingEventKind=purchase 常见于 SUBSCRIBED + INITIAL_BUY
  • billingEventKind=renewal 常见于 DID_RENEW

# 推送内容

如果 SUBSCRIPTION_WEBHOOK_URL 是钉钉机器人地址，函数会自动发 markdown 文本，内容会包含：

  • 平台
  • 应用
  • 地区
  • 类型：purchase / renewal / lifecycle
  • 事件名
  • 商品 ID
  • 金额
  • 订单号
  • 时间

钉钉消息标题和正文都会带上关键字 App，满足关键字校验。

如果 SUBSCRIPTION_WEBHOOK_URL 不是钉钉，则按 JSON POST 推送。

# 你现在最该怎么配

按你当前需求，建议就配下面这些：

# 必填

  • SUBSCRIPTION_WEBHOOK_URL 值填： https://oapi.dingtalk.com/robot/send?access_token=d8f93712f959a9e9a259d7adfbd88edc2c16291e1c68aa4348f68c1f6869e8ea
  • DINGTALK_KEYWORD 值填：App

# 建议

  • GOOGLE_ENDPOINT_SECRET 自己生成一个随机字符串，例如 google_sub_xxx
  • APPLE_ENDPOINT_SECRET 自己生成一个随机字符串，例如 apple_sub_xxx

# 如果你要拉 Google 详情

  • GOOGLE_SERVICE_ACCOUNT_EMAIL 填 service account 邮箱，例如 xxx@xxx.iam.gserviceaccount.com
  • GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY 填 service account 私钥全文，从 -----BEGIN PRIVATE KEY----- 到 -----END PRIVATE KEY-----

# 如果你要拉 Apple 详情

  • APPLE_API_KEY_ID App Store Connect API Key 的 Key ID
  • APPLE_API_ISSUER_ID App Store Connect 的 Issuer ID
  • APPLE_API_PRIVATE_KEY .p8 私钥全文
  • APPLE_BUNDLE_ID 你的 app bundle id，例如 com.example.app

# Cloudflare 里怎么填

路径：

Cloudflare Dashboard -> Pages -> wlang -> Settings -> Variables and Secrets

建议：

  • 普通字符串放 Variables
  • 私钥放 Secrets

推荐这样放：

# Variables

  • SUBSCRIPTION_WEBHOOK_URL
  • DINGTALK_KEYWORD
  • GOOGLE_ENDPOINT_SECRET
  • APPLE_ENDPOINT_SECRET
  • GOOGLE_SERVICE_ACCOUNT_EMAIL
  • APPLE_API_KEY_ID
  • APPLE_API_ISSUER_ID
  • APPLE_BUNDLE_ID

# Secrets

  • GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY
  • APPLE_API_PRIVATE_KEY

# 健康检查

GET /api/subscriptions/health

可以快速确认：

  • webhook 是否配置
  • Google/Apple 凭证是否配置
  • secret 是否配置

# 安全说明

当前实现已经做了：

  • 回调入口 secret 校验
  • Google 详情拉取鉴权
  • Apple Server API JWT 鉴权

当前还没有做：

  • Google Pub/Sub OIDC 来源验签
  • Apple 通知 JWS 证书链验签

如果这个接口长期公网开放，建议继续补这两项强校验。
